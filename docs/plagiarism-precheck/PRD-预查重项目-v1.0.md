> 作者：产品经理 许清楚

## 0. 一句话定位

大学生在正式送检知网 / 维普 / 万方之前，先用本工具低成本预估查重率，减少"查一次、改一次、反复花钱"的试错成本；预估结果通过用户回传的真实查重报告持续校准，逐步逼近目标平台真实结果。

---

## 1. 问题陈述

**谁**：本科 / 硕博毕业生，毕业论文进入修改期（毕业季前 2-3 个月）。

**什么场景**：学校要求论文查重率低于阈值（本科常见 20%-30%，名校 5%-10%，部分要求 AI 率 <20%）。学生需自行付费送检，改稿后反复送检，直到达标。

**痛点（有真实用户差评佐证）**：
1. **贵**：知网单次几十到上百元（黑市 198 元/篇，硕博 580 元/篇），反复查重花费可达上千元。
2. **不准 / 结果互相矛盾**：同一篇论文不同平台结果天差地别——实测知网 3.9% vs PaperPass 9%；知网 2.4% vs PaperYY 近 60%；AIGC 率知网 37.4% vs PaperPass 74%；有学生"维普更新前 6%，更新后 74%，之前 120 元白花了"。
3. **反复花钱循环**："学校查完重新修改，改了后自己付费查出来 19%，换另一家 6.8%，差距太大又得多出一份钱再找一家检测"（半月谈用户原话）。
4. **论文泄露风险**：假冒知网/万方/维普的公众号、淘宝账号泛滥，倒卖论文的灰色产业链存在。
5. **平台诱导消费**：格子达被投诉 59.9 元"智能质检"套餐欺诈；PaperPass 340 元"一键降 AI"改写跑偏（出现"食用油虫害"类无关内容）且退款困难。

**现在怎么解决**：免费工具（Paper 系）初筛 → 不准；直接送知网 → 贵、不敢反复送；电商代查/代降 → 泄露风险 + 质量差。

**为什么不行**：市场被切成"免费但不准"和"准但贵"两段，中间缺少"便宜且能预测知网结果"的工具。

## 4. 市场空白与机会点

1. **"预测知网结果"是空白**：现有玩家要么免费但不准（Paper 系），要么准但贵（知网）。没有一款工具"便宜 + 预判知网结果"。用户差评反复出现"平台间结果矛盾"，本质是**没有一个可信任的中间层**。
2. **校准训练是差异化护城河**：用户回传真实查重报告 → 模型逼近目标平台，这是现有竞品都没有的机制。样本越多越准，形成数据飞轮。
3. **本地版满足隐私诉求**：论文泄露是高频差评痛点（"同学论文被卖了"）。PyQt6 本地版离线查重 = "论文不出本机"，这是 Web 竞品给不了的信任点。
4. **预估定位规避合规风险**：不承诺"与知网一致"（法律风险 + 技术上不现实），而是输出"预估区间 + 置信度"，同时用校准持续收敛误差。用户要的是"心里有数"，不是"官方报告"。

**用户为什么选我们**：比免费工具准（校准逼近知网），比知网便宜（自研引擎 + 免费额度 + API 增值），比灰色渠道安全（本地版离线 + 脱敏授权）。

## 5. 核心功能（RICE 排序）

评分口径：Reach（1-10 季度受影响用户）、Impact（0.25/0.5/1/2/3）、Confidence（50/80/100%）、Effort（1-10 人月）。

| 功能 | Reach | Impact | Confidence | Effort | Score | 优先级 |
|------|-------|--------|------------|--------|-------|--------|
| 查重报告（总查重率 + 相似片段高亮 + 来源提示 + 导出 PDF/HTML） | 10 | 3 | 100% | 4 | 7.5 | **P0** |
| 文档上传查重（docx/txt/md/pdf → 分段 → 指纹 → 相似度） | 10 | 3 | 100% | 5 | 6.0 | **P0** |
| 多平台方案切换（知网/维普/万方模拟 + 第三方 API 增值） | 9 | 3 | 80% | 4 | 5.4 | **P0** |
| 账号与用量管理（注册/登录/免费次数/积分套餐） | 10 | 2 | 100% | 4 | 5.0 | **P0** |
| 校准训练系统（回传真实报告 → 配对 → 模型迭代 → 预估区间） | 8 | 3 | 70% | 6 | 2.8 | **P0（战略核心，评分受样本依赖拖累，MVP 必须闭环）** |
| 历史报告对比（多次查重趋势） | 6 | 2 | 80% | 3 | 3.2 | P1 |
| 批量查重（目录级） | 3 | 2 | 80% | 5 | 0.96 | P1 |
| 论文格式规范检测 | 4 | 1 | 60% | 4 | 0.6 | P1 |
| 降重改写建议 | 8 | 2 | 50% | 6 | 1.3 | **不做**（学术伦理 + 质量不可控） |

### 决策说明
- **校准系统评分 2.8 但定 P0**：RICE 衡量"单期价值/成本"，而校准是战略差异化（见第 4 节）。MVP 只需跑通"回传 → 线性回归 → 预估区间"闭环（架构师在 M2/M4 落地），完整价值随样本积累释放。
- **查重报告 + 上传查重合并理解**：上传是动作，报告是结果，两者共同构成"能用"的底线，MVP 缺一不可。
- **账号用量是"能收钱 + 防滥用"**：校内试点也必须有免费额度限制，否则自研引擎会被刷爆。

## 6. MVP 范围

仅保留 P0 五项，其余进 Backlog：

| 功能 | MVP 验收要点 |
|------|--------------|
| 文档上传查重 | 1 万字文档 30 秒内出结果；支持 docx/txt/md/pdf |
| 查重报告 | 总查重率 + 相似片段高亮 + 来源提示；可导出 PDF/HTML |
| 多平台方案切换 | 知网模拟 / 维普模拟 / 万方模拟 / 第三方 API 可选，配置可增删 |
| 账号与用量管理 | 注册登录、免费次数、积分或套餐；防止滥用 |
| 校准训练系统 | 用户回传真实报告 → 与预查重结果配对 → 线性回归 → 输出预估区间；随样本迭代 |

**Backlog（P1，二期）**：历史报告对比、批量查重、论文格式规范检测、第三方 API 付费深度增值。

**明确不做**：承诺与知网结果完全一致（报告附免责声明，呈现预估区间而非虚假精确）；论文代写/代改/代降（学术不端）；商业论文买卖。

## 7. 验收标准（Given/When/Then）

### 7.1 文档上传查重
- Given 已登录用户且剩余免费次数 > 0，When 上传一份 ≤10 万字的 docx 论文并提交，Then 系统在 30 秒内返回查重结果（Web 端为异步任务，轮询/回调通知）。
- Given 用户上传 .txt/.md/.pdf 格式，When 提交查重，Then 系统正常解析并出结果，无格式报错。
- Given 用户上传超过 10 万字或空文件，When 提交，Then 返回明确错误提示，不消耗免费次数。
- Given 用户剩余免费次数为 0，When 点击查重，Then 跳转充值/积分页，不进入上传流程。

### 7.2 查重报告
- Given 一次查重完成，When 用户打开报告页，Then 展示总查重率（预估中值）、相似片段高亮、来源提示、预估区间与置信度。
- Given 报告页展示预估区间，Then 预估区间必须以可见的可视化元素呈现（如误差带量规，中间刻度点为预估中值、色带覆盖区间范围），而非仅单一数字——这是"区间而非虚假精确"差异化的验收底线。
- Given 用户所在学校查重阈值已知（用户配置或默认 20%），When 预估区间与阈值线相交，Then 量规上绘制阈值线，并展示"预估区间跨过学校阈值，建议优先修改高亮片段"的行动指引。
- Given 校准样本不足，When 报告页展示预估区间，Then 色带自动变宽并提示"预估区间较宽，校准样本积累中，结果仅供参考"，不展示虚假精确数字。
- Given 用户点击导出，When 选择 PDF 或 HTML，Then 生成完整报告文件供下载，免责声明（"预估仅供参考，非官方检测报告"）随报告常驻。

### 7.3 多平台方案切换
- Given 用户选择"知网模拟方案"，When 提交查重，Then 引擎按知网模拟参数计算并展示知网预估区间。
- Given 系统配置新增一个 API 平台（架构师经适配层接入），When 用户选择该方案，Then 无需发版即可在方案列表中看到并可用。

### 7.4 账号与用量管理
- Given 未注册用户，When 点击查重，Then 引导注册/登录，注册完成即赠免费次数。
- Given 用户通过邀请/活动获得积分，When 查重，Then 优先扣除积分，积分余额实时可见。

### 7.5 校准训练系统
- Given 用户上传在某平台（知网/维普/万方）的真实查重报告，When 系统校验报告格式有效，Then 提取真实查重率并与该文档的历史预查重结果配对入库。
- Given 校准样本达到阈值（如 ≥30 条），When 触发模型训练，Then 生成新预估区间参数，下次查重使用新参数。
- Given 校准模型尚无足够样本，When 用户查看报告，Then 展示"预估区间较宽"的提示，不展示虚假精确数字。

## 8. 边界条件

| 场景 | 处理 |
|------|------|
| 空状态 | 报告页无数据 / 上传页未上传 → 展示引导文案与示例按钮 |
| 错误状态 | 解析失败 / 引擎异常 / 校准报告格式无效 → 明确错误码 + 可重试，不消耗免费次数 |
| 加载状态 | 异步查重任务 → 进度条 + 排队提示 + 完成通知 |
| 边界值 | 文件大小上限 10 万字；单文件 ≤50MB；超限拦截 |
| 并发 | 校内试点几百人，峰值按 100 并发估算，任务队列削峰 |
| 离线 | 桌面端本地版断网可跑基础查重，校准同步延迟到联网后 |
| 权限拒绝 | 未登录访问报告 → 跳登录；管理员/普通用户角色分离 |
| 隐私 | 用户文档默认脱敏入库（用户协议授权）；本地版默认不上传原文，仅上传指纹/特征 |

## 10. 数据埋点方案

MVP 必埋事件（不埋 = 上线后无法验证"校准逼近知网"假设）：

| 事件类别 | 必埋事件 | 说明 |
|----------|----------|------|
| 获客 | page_view, sign_up_complete | 新用户来源、注册转化率 |
| 激活 | first_check_complete | 用户完成第一次查重 |
| 核心验证 | report_uploaded, report_paired, calibration_sample_added | 校准样本回传链路（验证差异点假设） |
| 留存 | session_start, session_duration | DAU/MAU、使用频次 |
| 转化 | plan_switch（切换查重方案）, upgrade_click, payment_complete | 方案偏好 + 付费转化漏斗 |
| 异常 | error_occurred | 前端错误 + API 错误 |

**埋点实现要求**：
- 前端轻量 SDK（自建 `trackEvent()` 封装，避免引入重 SDK 增加包体积）
- 事件命名：`{对象}_{动作}`（如 `report_uploaded`, `payment_completed`）
- 属性：`user_id`, `timestamp`, `device`, `version`
- 不采集隐私数据（不上报 IP、不存原始文档内容，只上报事件元数据）
