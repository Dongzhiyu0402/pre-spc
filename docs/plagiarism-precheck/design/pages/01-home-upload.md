# 页面设计提示词：首页 / 上传页

> 路由：`/`（Web）｜桌面端同构（主窗口）
> 设计 Token 主题：Teal 主色
> 验收映射：AC-01 / AC-02 / AC-03 / AC-04 / AC-10 / AC-11 / AC-13
> 数据源：`POST /api/v1/checks`、`GET /api/v1/plans`、`GET /api/v1/checks`

---

## 1. 页面目标

工具工作台，不是营销站。用户进来第一眼看到**真实产品内容**（拖拽上传区 + 右侧真实报告卡 mockup），3 秒内知道"上传论文 → 预估查重率"的主路径。反千篇一律 Hero：禁止"大标题+副标题+居中 CTA+抽象图形"。

## 3. 核心组件与状态

### 3.1 拖拽上传区（核心交互）

| 状态 | 表现 |
|------|------|
| default | 2px dashed border --border，bg --surface，图标 --muted |
| hover / 拖入 | border --accent + bg --accent-soft，图标 --accent，文案"松开以选择" |
| 已选文件 | 收起虚线框 → 文件行（file-text 图标 + 文件名 mono + 大小 + 字数 + 移除 X） |
| 校验失败 | 文件行下错误文案（--danger），红色边框，**不消耗次数**（AC-03） |
| 上传中 | 进度条（Progress，colorPrimary Teal）+ 排队提示 |
| disabled | 免费次数为 0 时，点击 → 跳转用量/充值页（AC-04），不进入上传 |

### 3.2 方案卡片单选（AC-10/AC-11）

- 4 张卡片（桌面 4 列，移动 2 列）：方案名 + 类型徽标（"自研模拟"/"API"）+ 价格说明
- 选中态：border --accent + bg --accent-soft + 对勾（Lucide check）
- 默认选中"知网模拟"（用户最关心）
- 新增 API 方案无需发版即出现（AC-11，数据来自 GET /plans）

### 3.3 真实报告卡 mockup（反千篇一律 Hero）

- 静态展示，但必须"真实"：有具体数字（如 18.6% + 区间 14–24%）、量规、章节条、标红片段
- 标注"示例报告"避免误导；hover 轻微上浮（--elev-raised，200ms）
- 目的：让用户第一眼知道"我能得到什么"

## 4. 交互流

1. 进入首页 → GET /plans 加载方案 → 渲染上传区 + mockup
2. 拖入/选择文件 → 校验 → 显示文件行
3. 选方案 → 点"开始检测" → POST /checks → loading（进度+排队提示）
4. 完成 → 跳转 `/report/:id`
5. 免费次数为 0 → 跳转用量页（AC-04）
6. 未登录点击"开始检测" → 跳登录（注册赠次数 AC-12）

## 5. 响应式

- <768px：左右栏堆叠（上传区优先）；方案卡 2 列；mockup 可隐藏或移至下方（保持首屏 = 上传区）
- 触摸目标：上传区整块可点；开始检测按钮 44px 高；文件移除 X ≥44px 热区

## 6. 文案（禁空洞占位）

- H1：`上传论文，预估查重率`
- 副标题：`送检前先预估，输出预估区间与置信度，省下反复送检的钱`
- 上传提示：`拖拽论文到此处，或点击选择`
- 格式说明：`支持 docx / txt / md / pdf · 单文件 ≤50MB · ≤10 万字`
- CTA：`开始检测`（不用 "Submit"/"Get Started"）
- 隐私：`文档默认脱敏后入库，可随时删除`

## 7. 验收映射速查

- AC-01：登录 + 次数>0 + 上传 docx → 30 秒内出结果（异步进度可见）✓
- AC-02：txt/md/pdf 正常解析 ✓
- AC-03：超限/空文件 → 明确错误 + 不消耗次数 ✓
- AC-04：次数 0 → 跳用量页 ✓
- AC-10/11：方案切换 + 动态出现 ✓
- AC-13：查重优先扣积分且余额实时可见（用量入口）✓
