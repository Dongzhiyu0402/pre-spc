# 页面设计提示词：历史记录页

> 路由：`/history`（Web）｜桌面端同构（QTableWidget/QListWidget）
> 设计 Token 主题：中性
> 数据源：`GET /api/v1/checks?page=&limit=`

---

## 1. 页面目标

"写改循环 5-10 次"的用户核心诉求是**再次检测**和**找回上次报告**。列表信息密度高但不压迫（Density=5），一眼看到：文件、方案、时间、状态、结果入口。

## 2. 布局

```
┌─────────────────────────────────────────────────────┐
│ 顶部导航（返回首页）                                   │
│ H1：历史记录（20px semibold）+ 筛选（方案/状态下拉）     │
├─────────────────────────────────────────────────────┤
│ 列表（卡片式行，hover 高亮）                           │
│  [file-text] 论文开题报告.docx  知网模拟  08-05 21:30  │
│      字数 1.2万 · 已完成 → [查看报告] [再次检测]         │
│  [file-text] 实验方法.docx      维普模拟  08-05 20:10  │
│      字数 0.8万 · 已完成 → [查看报告] [再次检测]         │
│  [file-text] 文献综述.md        知网模拟  08-05 19:40  │
│      字数 0.5万 · 检测中(进度) → [查看进度]             │
├─────────────────────────────────────────────────────┤
│ 分页（Pagination，AntD 默认控件图标可保留）             │
└─────────────────────────────────────────────────────┘
```

## 3. 核心组件与状态

| 状态 | 表现 |
|------|------|
| Populated | 列表行：文件图标 + 文件名（md）+ 方案标签（Tag：知网模拟/维普模拟/万方模拟/API）+ 时间（meta）+ 字数（mono sm）+ 操作按钮 |
| 操作 | [查看报告] Button ghost（--accent）→ /report/:id；[再次检测] Button secondary → POST /checks/{id}/recheck → 跳转/loading |
| Empty | 空态：居中 file-search 图标（Lucide 24）+ "还没有查重记录" + CTA"上传第一篇论文"→ 首页（引导文案 + 操作按钮） |
| Loading | 列表骨架屏（3 行占位 + 微光） |
| Error | "加载失败，请重试" + 重试按钮，不消耗次数 |
| Edge | 检测中任务：显示进度条（Progress）+ "查看进度"；超长文件名截断（ellipsis + title 提示） |

## 4. 交互流

1. 进入 /history → GET /checks → 渲染列表
2. 点"查看报告" → /report/:id
3. 点"再次检测" → POST recheck → loading → 完成后跳新报告（AC 流程对齐）
4. 筛选方案/状态 → 客户端或服务端过滤

## 5. 响应式

- 移动端：行内操作收进"更多"菜单（避免行内按钮拥挤）；时间/字数可折叠到第二行
- 触摸目标：行高 ≥56px；操作按钮 ≥44px 热区

## 6. 文案（禁空洞占位）

- 空态：`还没有查重记录，上传第一篇论文试试` + CTA `上传论文`
- 错误：`历史记录加载失败，请重试`
- 操作：`查看报告` / `再次检测`（动词 + 明确对象）

## 7. 验收映射

- GET /checks 分页返回 ✓；再次检测链路 ✓；空态引导 ✓
